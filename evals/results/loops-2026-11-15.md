# Loop repair eval

Run 2026-11-15. Aggregates and time spans only, on public corpora (AMI SDM, AliMeeting far-field); no transcript or
reference text.

## What was measured

Whole-call decodes (`w-prod`, and each run of `w-runs-lid`) used to keep a decoder loop and flag the whole row with
`decoder_anomaly`. With the repair, the 30 s Whisper window that fails the quality guard is decoded again as two halves
and spliced back; only windows that still fail are flagged.

The flagged set was fixed before the run: every row with `decoder_anomaly` in the E2 language-policy runs.

| hypothesis | corpus | recordings |
|---|---|---|
| `w-prod` | AMI | TS3003b |
| `w-prod` | AliMeeting | R8008_M8013, R8009_M8020 |
| `w-runs-lid` | AliMeeting | R8001_M8004, R8008_M8013, R8009_M8019 |

Their worker folders were moved out of the live layout, the files were decoded again with the repair, and
`rescore` compared the two:

```bash
uv run python -m evals.run_recordings_asr run --hyp w-prod --corpus alimeeting --recordings R8008_M8013,R8009_M8020
uv run python -m evals.run_recordings_asr rescore --hyp w-prod --corpus alimeeting \
  --recordings R8008_M8013,R8009_M8020 --before "$ANYVERBATIM_EVAL_DIR/recordings/asr-loops-before-2026-11-15"
```

## Fresh decodes that differ outside the repair

A window that falls back to sampling (temperature above 0) is not reproducible, so a new decode can differ from the
old one where nothing was repaired.

- **AMI TS3003b (`w-prod`):** the old loop (1309–1346 s, 123 words) did not recur, so nothing was repaired. The new
  decode differs over 1297–1455 s, where it kept 2 words instead of the loop. 98.1% of the other words are identical.
  `w-prod` decodes this file as Nynorsk, so its high WER says nothing about the repair.
- **AliMeeting R8001_M8004 (`w-runs-lid`):** nine differences over 344.8–571.4 s surround the one repaired window, and
  97.6% of the words outside it are identical. File CER moved from 53.27% to 53.99%.

## Pre-registered rules

| rule | result | outcome |
|---|---|---|
| 1. The repair ships unless the error is worse after, with the window CI entirely above 0 | no hypothesis or corpus has a CI above 0 | **ships** |
| 2. Stop if more than half of the looped windows still flag after their re-decode | 0 of 9 | continue |
| 3. Plan a seam dedupe if more than a quarter of the repaired windows have a seam duplicate | 0 of 9 | not planned |
| 4. Report every row flagged with no span | none | — |

## End to end

Two recordings through `anyverbatim run` on the repair branch.

- **ASCEND session 1** (15.6 min, `--engine w-runs-lid`, default LLM). Before the repair, its first run looped
  (a phrase repeated 13 times before 3:58), and the whole-run flag footnoted 76 of 83 footnotes `decoder_anomaly`.
  The fresh decode made the same request, with the same fingerprint, and did not loop: its runs carry no flag, the
  document has no `decoder_anomaly` flag or footnote, and no phrase repeats three times in a row at 3:30–3:58. That
  loop came from a window that does not reproduce, so this run checks the unflagged path, not the repair.
- **AliMeeting R8008_M8013** (37 min, `--engine w-prod`, `--llm none`), whose loops recur on every decode. The row
  comes back `redecoded`, with no `decoder_anomaly` and no spans. `quality.flags_by_kind` counts one `redecoded`, the
  Markdown has no decoder footnote, and no phrase repeats three times in a row at 5:18–5:46 or 15:55–16:30.
