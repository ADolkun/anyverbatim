# Two language tokens for mixed recordings (TE)

Run 2026-11-16. Aggregates only, on public corpora; no transcript or reference text. The decision rule was fixed
before the run (the two-token plan's §6.2) and is applied below as written.

## What was compared

Both hypotheses are Whisper large-v3 with the production temperature schedule and no language hint.

| hypothesis | decode |
|---|---|
| L `w-runs-lid` (the recordings default) | speech chunks, language detected per chunk among zh and en, same-language chunks merged into runs, each run decoded with its one language token |
| H `w-runs-cs` | the same runs; in a recording whose languages are zh and en, each run is decoded with both tokens in the start sequence, its own language first (`<\|startoftranscript\|><\|zh\|><\|en\|><\|transcribe\|>`) |

A monolingual recording decodes the same way under both, so AMI and AliMeeting differ only where Whisper's sampled
fallback windows differ. Corpora as in [language-2026-11-15.md](language-2026-11-15.md): AMI (6 English meetings,
WER), AliMeeting (8 Mandarin meetings, CER), the 4 ASCEND code-switched sessions and their 1315 utterances (MER).
Error rates use the `itn` view; intervals are paired bootstrap 95% CIs over recordings (`decision`), seed 0.

**Clean lines** are reference lines of at least 3 units, at least 70% one script, in a recording whose reference
holds both scripts, overlapping no other line: 418 session lines and 301 utterances.

## Integrity stop and fix

The first run stopped at the integrity gate. One row of an ASCEND session held a sampled language token (`<|ms|>`) as
text: mlx-whisper's default suppression covers non-speech tokens but no language token, and its decoder keeps a sampled
one in the text. As pre-registered, the fix was to suppress every language token in a two-token decode
(`suppress_tokens` = `-1` plus the model's language tokens). The sessions and utterances were then decoded again; AMI
and AliMeeting decode one language and were kept.

The fix changed one session only: 763 → 828 errors, +0.57 points of MER over the four sessions (CI [+0.00, +2.57]).
The other three sessions are identical. For the record, the stopped run read P1 11 fixed and 4 introduced (p = 0.059)
and P2 −0.09 points [−0.51, +0.38]; it decides nothing.

## Translation incidents on clean lines

An incident is a clean line whose hypothesis renders it in the other script. Paired over the same lines; the test is
a one-sided exact sign test on the lines where only one hypothesis has an incident.

| set | lines | L | H | fixed by H | introduced by H | p |
|---|---|---|---|---|---|---|
| ASCEND sessions | 418 | 16 | 9 | 11 | 4 | 0.059 |

## Decision

| gate | pre-registered rule | result |
|---|---|---|
| Integrity | no H row holds `<\|`; H rows of AMI, AliMeeting and the utterances carry one language per recording | pass: 0 rows, 0 recordings |
| P1 | pooled clean-line incidents: H fixes more than it introduces, sign test p < 0.05 | **fail**: 11 against 4, p = 0.059 |
| P2 | pooled MER: point ≤ 0 and CI upper bound ≤ +0.5 points | **fail**: +0.20 [−0.42, +0.78] |
| N | AMI and AliMeeting: CI upper bound ≤ +0.5 points | pass: +0.00 and +0.08 |

The table's row for "P2 point > 0, CI includes 0, N pass" gives **Reject**. `w-runs-cs` is not merged, the incident
counting is kept for any pair of hypotheses, and `w-runs-lid` stays the default for recordings with
`[asr] languages`.

Two tokens cut the session incidents from 16 to 9 (11 fixed, 4 introduced), but that is not significant on this data.
They changed no utterance's incident, and the session error rate moved the wrong way.

## Reported, not gated

- **All lines** (chunk incidents in mixed recordings): ASCEND sessions L 102 (11.4%), H 93 (10.4%); utterances 8 and 8;
  AliMeeting L 0, H 2 (none on clean lines).
- **Repairs:** no `decoder_anomaly` and no `redecoded` row in H's sessions.
- **Monolingual identity:** 99.96% of H's AMI words and 98.76% of its AliMeeting words equal L's.
- **Han characters in English rows** (sessions): L 145, 7 of them Traditional; H 209, 44 Traditional. Script
  conversion runs only in zh stretches, so these stay as decoded.
- Deletions and insertions are not broken out by the scorer.

## How it was produced

From a worktree of the two-token branch, which is not merged:

```bash
uv run python -m evals.run_recordings_asr run --hyp w-runs-cs
uv run python -m evals.run_recordings_asr score --hyp w-runs-cs
uv run python -m evals.run_recordings_asr score --hyp w-runs-lid
uv run python -m evals.run_recordings_asr compare --a w-runs-cs --b w-runs-lid
# after the suppression fix, with the stopped run's worker folders moved aside:
uv run python -m evals.run_recordings_asr run --hyp w-runs-cs --corpus ascend --corpus ascend-utterances
uv run python -m evals.run_recordings_asr rescore --hyp w-runs-cs --corpus ascend --recordings ses1,ses2,ses3,ses4 --before DIR
```
